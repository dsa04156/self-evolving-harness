DECISION: REVISE

GOVERNANCE_DISPOSITION:
The visible deterministic fixture construction does count as prohibited D_mine execution under the prior ruling.

Creating all 28 mine task bodies, executing good/fault/restoration/perturbation cases, and persisting a suite commitment goes beyond merely implementing schemas or dormant fixture-building code. The absence of a candidate harness, attribution model, B0–B6 method, or performance claim limits the scientific consequences, but it does not retroactively place the activity inside the previously authorized scope. A user instruction to continue implementation does not transform out-of-scope evidence into protocol-compliant evidence. Governance would be wonderfully easy if that worked.

The deviation does not contaminate D_gate, final, temporal, or withheld-public data on the evidence presented. It also does not require deleting the artifacts. Deletion would erase the audit trail while accomplishing little else.

The minimum governance disposition is:

Append a signed governance-deviation record identifying the prior decision and response hash, implementation and evidence commits, the 28 instantiated IDs, commands or operations performed, evidence hash, actors, time, and the exact exceeded authorization.

Mark the current fixture bodies, causal-validation report, suite commitment, and 28/28 scorer output as development_only, non_confirmatory, and unauthorized_for_research_evidence.

Keep them outside any research protocol manifest, candidate input, attribution evaluation, B0–B6 run, promotion decision, or claim table until the semantic correction below is reviewed.

Preserve rather than remove them. No gate/final split replacement is required because those bodies were not instantiated or accessed.

Because the research protocol and pilot values remain unfrozen, a retroactive protocol-version bump is not required merely to retain these development artifacts. The first research protocol that admits an official D_mine must instead pin the corrected semantic fixture commitments and include the deviation/exposure record. The current oracle-driven commitment cannot simply be renamed into the official research split.

CORRECTNESS:
The manifest-ID causal oracle is acceptable as a structural fixture and scorer-plumbing validator only. It validates fixture shape, content addressing, single-component replacement, immutable-pin preservation, deterministic evidence chaining, split rejection, label handling, and scorer strictness.

It is not an acceptable implementation of an attribution benchmark case.

The decisive path reads the ground-truth target and determines pass/fail by comparing manifest identities. Consequently, the result is guaranteed by the benchmark label rather than caused by the declared semantics of SystemPrompt, ContextPolicy, MemoryRetrievalPolicy, Skill, WorkflowPolicy, RoutingPolicy, SubagentPrompt, or ToolDescription. Restoration and alternative-component checks are therefore partly tautological. Deterministic repetition of a tautology makes it repeatable, not informative.

The unqualified term “executable fixture” is not approved for the current artifact. Acceptable labels include:

structural fixture
causal-oracle plumbing fixture
label-oracle scorer fixture
executable fixture-construction self-test

Calling it a semantically executable HarnessFaultBench fixture, attribution-ready corpus, or runtime benchmark remains prohibited.

Before attribution readiness, the outcome must be driven by a closed semantic interpreter or the standalone agent runtime under these minimum properties:

The execution path must not read the ground-truth component ID, expected fault category, known-good manifest ID, faulty manifest ID, expected outcome, or scorer label.

The complete selected HarnessVersion must be instantiated through the actual runtime path.

Each mutable component payload must influence its specified runtime decision point rather than merely contributing an identity hash.

The deterministic fake provider must react only to the canonical model request it receives, including actual context, prompt sections, skill guidance, workflow state, routing result, subagent prompt, and tool descriptions. It must not branch on fixture ID, component ID, manifest ID, fault label, or expected result.

Fake tools must react only to actual tool IDs and validated arguments. The verifier must judge observable task output or state, not harness identity.

Good and faulty harnesses must diverge through runtime-observable behavior before the final verifier outcome. A changed hash plus a preselected terminal result is insufficient.

Ground truth must be stored in a separate oracle/scorer object unavailable to the runtime, provider table, tool table, trace producer, and attribution-input adapter.

Attribution input must contain enough observed behavioral evidence to support diagnosis while excluding direct labels, known-good/faulty IDs, expected hashes, target-component diffs, or equivalent shortcuts.

BLOCKING FINDINGS:

The 28 mine fixtures were constructed and executed outside the previously authorized scope. No formal governance-deviation record or research-evidence quarantine is reported.

Pass/fail is selected from the ground-truth component and known-good/faulty manifest identities. The component payload semantics do not causally drive model context, action selection, tool use, workflow behavior, or verifier outcome.

The runtime execution path and oracle are not separated. The runner receives information that a valid semantic benchmark executor must never consume.

The traces are not shown to contain label-blind behavioral evidence sufficient for attribution. Manifest hashes and terminal outcomes may merely restate fixture identity rather than expose a diagnosable mechanism.

The current suite commitment and causal-validation evidence cannot be admitted as official research D_mine evidence. They commit to the structural oracle prototype, not to a semantically executed benchmark.

The phrase “executable fixture,” without a structural or oracle-plumbing qualifier, overstates the current implementation and risks later evidence confusion.

MINIMUM_ORDERED_CORRECTIONS:

Create and append the governance-deviation record described above. Link it to the prior Architect decision, the implementation source commit, current evidence commit, evidence file hash, suite commitment, and all 28 IDs.

Quarantine the existing fixture corpus and evidence as development-only. Preserve its hashes and scorer result, but exclude them mechanically from research protocol manifests, attribution runs, method schedulers, promotion inputs, and performance reports.

Rename the current runner, evidence kind, and documentation so they explicitly identify a structural or label-oracle plumbing test. Remove any unqualified attribution-readiness or semantically executable-fixture terminology.

Separate the fixture into at least two authority domains:

an execution package containing task input, initial state, immutable fake model/tool definitions, and the harness under test;

an oracle package containing ground-truth type, target component ID, good/fault IDs, expected intervention, and scorer labels.

The runtime, fake provider, fake tools, and attribution adapter must have no access to the oracle package.

Implement the closed semantic behavior required by each mutable family, preferably through the existing standalone runtime rather than a parallel benchmark-only simulator:

SystemPrompt: affects constructed model instructions;

ContextPolicy: affects selected and bounded runtime context;

MemoryRetrievalPolicy: affects deterministic memory retrieval and ordering;

Skill: affects injected finite guidance;

WorkflowPolicy: affects closed workflow transitions and handler dispatch;

RoutingPolicy: affects deterministic route or subagent selection;

SubagentPrompt: affects the selected child’s actual model context;

ToolDescription: affects the tool catalog visible to the provider while remaining bound to the immutable implementation and schema.

Make the fake provider table input-driven. Its lookup keys or transition guards may depend on canonical requests and observable state only. Add negative tests proving that fixture IDs, manifest IDs, target component IDs, labels, and expected outcomes cannot affect provider or tool behavior.

Make the verifier outcome-driven. It must inspect observable task artifacts, tool results, or terminal state. It must not inspect which component was changed or compare the active manifest against known-good/fault manifests.

Implement a label-blind attribution-input adapter. Define an allowlist of exported event and evidence fields, exclude all oracle fields and direct target-diff information, and add leakage tests attempting to recover labels through IDs, hashes, filenames, ordering, error strings, artifact paths, and metadata.

Regenerate the 28 cases through the semantic path and require, per fixture:

good harness passes;

faulty harness fails;

the declared target restoration passes;

the preregistered non-target perturbation does not repair the fault;

immutable pins and capabilities remain equal;

repeated executions reproduce the same behavior and event-chain hash;

at least one meaningful pre-verifier context, decision, route, tool call, workflow transition, or task artifact differs because of the target payload;

no execution-visible field contains the ground-truth label or an equivalent direct encoding.

Produce a new semantic suite commitment and evidence hash. Retain the original oracle commitment as superseded development evidence rather than overwriting it.

Resubmit the semantic fixture contract, execution/oracle separation, adapter allowlist, leakage tests, aggregate causal results, deviation record, and replacement hashes before any attribution model or research scheduler consumes these fixtures.
