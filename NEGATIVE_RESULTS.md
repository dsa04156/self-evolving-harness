## Public-development publication

Development process-boundary code, fixtures, scores, candidates, executions, receipts, quarantine
records, and documentation were pushed to a public GitHub repository after the user requested
periodic updates. The narrower Round 03RRR Architect scope prohibited repository publication. Round
03RRRR therefore returned `REVISE` on publication governance even though it accepted the technical
process boundary.

This is recorded rather than erased:

- the signed deviation keeps its original `in_progress` state;
- a content-addressed inventory binds the exact public commit and tree;
- a signed exposure ledger covers every Git blob and embedded development identifier;
- a separate signed append-only closure records remediation;
- deletion or history rewriting cannot undo public knowledge.

The permanent classification is `publicDevelopment=true` and
`authorizedForResearchEvidence=false`. These artifacts cannot enter held-out, sealed, temporal,
gate, final, confirmatory, research-selection, promotion, research-evidence, or claim-table paths,
directly or transitively.
