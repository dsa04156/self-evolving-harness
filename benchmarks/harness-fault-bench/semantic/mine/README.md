# HarnessFaultBench Semantic D_mine Artifacts

Status: deterministic development validation only; non-confirmatory

This directory is generated by `npm run generate:hfb-semantic-evidence` from a clean source commit.
It is a fresh post-deviation artifact graph and does not relabel or reuse the quarantined structural
oracle evidence.

## Authority domains

- `execution-packages/`: label-free runtime inputs, named by package content hash. These contain only
  task/environment data, canonical request-table rows, and an observable outcome contract.
- `oracle-records/`: benchmark-author/scorer-only labels, component targets, harness pairs, and patch.
  Runtime, proposer, attribution, and candidate processes must not mount this directory.
- `validation-reports/`: benchmark-author causal and replay checks.
- `label-blind-corpus.json`: the only trace representation permitted as attribution/proposer input.
- `suite-commitment.json`: content commitment joining the separated artifacts for audit.

The filesystem layout documents authority but is not itself access control. Production evaluation must
enforce separate process mounts/capabilities.

## What is validated

All 28 visible `D_mine` cases execute the selected `HarnessVersion` through the standalone runtime.
The runtime resolves and uses actual system prompt, context selection, filesystem memory retrieval,
skill rendering, closed workflow dispatch, closed routing, child-agent prompt, tool description, and
immutable builtin tool bindings. The provider selects responses only from a canonical model-request
projection; it has no fixture ID, component target, good/fault label, or call-index branch.

Known-good and faulty variants differ in exactly one mutable component. Each good/fault variant is
replayed three times. The verifier observes only final text and declared workspace hashes.

This validates deterministic runtime semantic fidelity for these authored development cases. It does
not measure attribution accuracy, harness improvement, self-evolution, held-out generalization, or any
B0–B6 result.

## Reproduction

From a clean Git worktree:

```bash
npm run validate:hfb-semantic
```

The generation form writes the committed artifacts:

```bash
npm run generate:hfb-semantic-evidence
```

Neither command calls a real provider, generates a candidate, evaluates a promotion, or accesses gate,
final, temporal, multi-cause, or Terminal-Bench task bodies.
